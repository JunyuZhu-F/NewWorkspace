# 论文复现项目：旧会话结束前的上下文交接

我准备结束当前 Codex 会话，并在新窗口继续同一个论文复现项目。

当前工作区：`D:\NewWorkspace`

请执行一次**基于真实工作区状态的增量交接**，确保新窗口无需依赖本次聊天历史，也能准确恢复项目进展。

本轮只允许必要的状态检查和交接文档更新，不允许继续推进新的论文复现任务。

## 一、识别当前项目与真实现场

1. 确认当前论文项目的真实目录，不要猜测项目路径。
2. 检查适用的工作区根目录及项目级 `AGENTS.md`。
3. 按需读取 `STATE.md`、`TASK.md`、`REPRODUCTION_PLAN.md` 和必要的 `EXPERIMENTS.md` 内容。
4. 检查实际目录、相关代码、配置、测试和当前 Git 状态。
5. 检查本会话确实执行过的操作，以及可用的运行记录和验证证据。
6. 识别未提交的代码修改、未完成任务、尚未结束的进程及潜在数据保护风险。

禁止为了交接而递归读取整个工作区、全部历史笔记、大型日志或所有实验输出。

## 二、核对真实科研进度

结合项目文件、实际代码和证据，确认：

1. 最近真正完成了哪些任务。
2. 哪些任务已经通过验证，具体证据是什么。
3. 哪些代码或配置发生过修改。
4. 最近一次有效测试或实验的执行状态、结果和证据路径。
5. 哪些任务仍在进行、阻塞或待验证。
6. 当前论文复现计划是否与真实实现和实验状态一致。
7. 是否存在文档描述与实际文件不一致的情况。

明确区分：

- 已验证；
- 合理推测；
- 待验证；
- 未开始；
- 失败或阻塞。

不得将“文件已创建”“代码已编写”或“曾计划执行”直接作为任务完成的证据。

如果前面多次上下文压缩导致无法确认某项历史操作，请从工作区和现有证据核实。无法核实的内容明确标记为待确认，不能凭残余聊天上下文推测。

## 三、增量更新持久化文件

按照现有文档职责，只更新确实需要更新的内容。

### 1. EXPERIMENTS.md 与实验记录

仅当实验记录、状态或结果发生变化时更新。

保存真实实验编号、代码版本、配置、运行状态、测试结果和证据路径。

不要重新整理全部实验历史，不要覆盖原始证据。

### 2. REPRODUCTION_PLAN.md

仅当任务状态、依赖、完成证据、阻塞或下一步发生变化时更新。

- 保持当前论文专属的阶段和任务编号。
- 不强制套用固定 P0–P12 流程。
- 已完成任务必须有经核验的证据。
- 证据失效时，重新检查相关任务及下游依赖。
- 不为了交接重构已确认的整个计划。

### 3. STATE.md

作为新窗口的主要恢复入口，确保准确记录：

- 最近更新时间；
- 当前复现阶段和任务编号；
- 已完成且经过验证的重要成果；
- 最近一次真实测试及实验结果；
- 当前代码、Git、环境与运行现场；
- 未解决问题和阻塞；
- 重要技术决策及其依据；
- 下一步最优先的具体操作；
- 必须保留的工作现场及注意事项。

保持简洁，引用已有文件路径和实验编号，不复制完整日志。

### 4. TASK.md

仅在研究目标、复现范围、约束或最终验收标准发生实质变化时更新。

不要将阶段进度、执行流水账或交接详情重复写入 TASK。

## 四、决定是否需要额外交接报告

优先依靠现有 `STATE.md` 完成交接。

只有出现以下情况时，才在 `notes/` 中新建简短的交接报告：

- 当前存在复杂且无法通过 STATE 简洁表达的临时现场；
- 多个相互依赖的未提交修改需要详细说明；
- 有重要历史决策或未解决异常需要额外保存。

否则不新建交接文件。

不要为了形式而生成大量带时间戳的重复交接报告。

## 五、交接安全约束

- 不继续开发新功能。
- 不修改核心算法或实验协议。
- 不启动训练、大规模测试或耗时实验。
- 不擅自终止正在运行的程序。
- 不自动提交、推送、清理或重置 Git。
- 不删除或覆盖代码、数据、日志及历史成果。
- 不擅自修改其他论文项目。
- 不因为整理文档而改变实验结论。

若 Git 工作区存在修改，必须准确记录并保留。

## 六、最终输出交接摘要

请简明报告：

1. 当前项目路径与任务编号；
2. 当前阶段及真实完成情况；
3. 最近一次测试或实验及验证结果；
4. 本轮实际更新了哪些文件；
5. 当前 Git 和运行环境状态；
6. 未解决问题和风险；
7. 新窗口应首先执行的具体操作；
8. 新窗口必须读取的最少文件清单。

最后明确说明：当前交接是否具备新会话独立恢复的条件；如不具备，指出缺失的证据或状态。

完成后停止，不要自动继续论文复现。
