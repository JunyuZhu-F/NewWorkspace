## 1. 为什么这样安排

这篇论文复现的是三个目录索引方案，不是训练模型。先弄清一个目录应包含哪些 ID、移动后归谁，再写索引；否则跑得快也可能只是漏了候选。之后先测目录成本，最后才接向量搜索，避免把目录错误、ANN 误差和相关性评分混在一起。

数据已在场，但部分“做题规则”缺失：WIKI 查询目录、DSM 操作清单、ARXIV 两套查询用途和 Viking 参数。可以设计独立可重复的替代协议，但要先审核并标注，不能称为作者原始工作负载。

主线：**审核范围 → 数据与语义核对 → 独立判定器 → 三方案正确性 → 小规模目录成本 → 同后端检索 → 审批扩规模 → 逐目标验收**。WIKI 缺口只阻塞对应实验，不妨碍人工小树工作，也不意味着可以静默省略 WIKI 目标。

## 4. 实现与正确性：先小树，再真实数据

建议用 C++ + 同版 Roaring，减少语言和集合实现差异；平台由 REVIEW-01 决定。判定器可以简单、慢，但必须独立于被测索引。不能把判定器内部结构作为某一方案的额外缓存加速基线。

检查至少覆盖：

- 同祖先/跨分支 MOVE；向量和 entry ID 不变，catalog 与新路径一致，共同祖先不误减/重复加。
