# SPEC-01：目录操作约定与人工验收案例

2026-10-26。本文先明确论文能够支持的**单父目录核心**，作为当前实现语义规范。源码、审查和运行结果统一见 core-review.md，本笔记保留规则与手工预期，不复制日志。单父目录部分的规则已书面确定；真实 ARXIV 多类别如何进入 DSM 仍待确认，不能以本文掩盖该缺口。

来源标签：**原文**指论文直接描述；**项目约定**是原文未完整规定时为可检验接口作的明确选择；**待确认**不得作为作者方法声称。

## 1. 对象与合法域

- **原文**：目录形成树，条目 ID 表示逻辑 payload；catalog 记录条目的逻辑父目录。TrieHI 节点字段与不变量见 PDF p. 6 §IV-A，唯一公式 (1)。
- **核心合法域**：在同一个受测目录树中，一个 entry ID 只直接归属一个目录；ID 对应的向量在目录 MOVE/MERGE 时不变。三个方案和独立判定器处理相同逻辑输入。
- **项目约定**：API 的目录按路径段区分；大小写与 Unicode 码点保持原样，不自动小写或进行 Unicode 规范化。`/a/` 不包含 `/ab/`，同名段可位于不同父目录。
- **项目约定**：根为 `/`；接口规范路径有前导/末尾 `/`。内部可按路径段表示，拒绝 `.`、`..`、重复内部分隔符和空段，不解析符号链接。合法路径段的原始内容不改写。
- ARXIV 原始路径缺前导 `/` 时，只允许在数据适配说明中明确建立接口视图；保留原值及对应关系，不能把 `1991/7/` 悄悄改为 `1991/07/`。原始文件保持只读。
- 在场 WIKI 路径样本适合单归属模型；ARXIV 时间字段在已读样本中为单路径，可能用于单命名空间检查。**尚未验证全库，也未宣称作者就这样拆分命名空间。**
- ARXIV category 多归属不能直接进入这一单父目录 DSM 合法域。不能静默取第一类别、复制 payload 成新 ID 或新增引用计数。这些若未来采用，必须作为有来源的协议或明确的实验性扩展。
- 后续定点核查发现 categories 可同时列出祖先路径与严格后代（如 id=40238 的 `Physics/nlin/` 与 `Physics/nlin/nlin.CD/`）。因此列表路径相等不能未经核实就解释为直接绑定 Local；真实类别非递归/维护协议尚未冻结。证据和不同解释的影响见 `data-audit.md` §9。

## 2. 必须一直成立的规则

令 `Local(v)` 为直接归属 v 的 ID 集合，`Child(v)` 为直接孩子，`Inc(v)` 为全子树集合：

\[
Inc(v)=Local(v)\cup\bigcup_{w\in Child(v)}Inc(w).
\]

**原文：**PDF p. 6，公式 (1)。Local 是语义定义，不意味着给 TrieHI/PE-OFFLINE 增加一个直接 posting 查询缓存。

每个操作完成后验证：

1. 父子连接一致、树无环，每个非根目录只有一个父节点。
2. catalog 的每个 ID 恰有一个逻辑父目录，且所有 ID 与向量映射不因目录变更改变。
3. 所有受影响节点满足公式 (1)，不能只检查根的条目数量。
4. 全局 payload ID 集合不因 MOVE/MERGE 增减；重复目录名称不意味着 payload ID 可以被覆盖。
5. 维护结束后旧路径与新路径可见性符合操作定义；失败的输入检查不改变任何状态。

最后一项失败行为是项目接口约定。初版为单线程顺序执行，不声称并发原子性、事务持久化或故障回滚。

## 3. 操作输入输出

| 操作 | 语义与输入 | 输出/状态变化 | 定位或项目约定 |
|---|---|---|---|
| 插入 | 新 ID、向量引用、一个逻辑父目录 | 创建缺失目录；条目只直接归属终点；按方案更新 posting/Inc 和 catalog | 原文 PDF pp. 4–6；相同 ID 重复插入初版拒绝，更新 payload 不纳入此接口 |
| 递归 DSQ | 一个目录锚点 p | 返回 p 与所有后代的合法 ID 集合 | 原文 PDF pp. 3–7；不排名向量 |
| 非递归 DSQ | 一个目录锚点 p | 只返回直接归属 p 的 ID | 同上；PE-OFFLINE/TrieHI 按子树并集做差 |
| MOVE | 源目录 s、新父目录 d | 源根名称不变，变为 d 的孩子；整个子树内部关系和 ID 保持 | 原文 PDF pp. 3–5、7；不是将源根内容直接合进 d |
| MERGE | 源目录 s、目标目录 d，互不包含 | 源根直接条目归入 d；同名孩子递归合并，不冲突孩子转挂；源根绑定消失 | 原文 PDF pp. 3–5、7；源根直接条目保留是语义及 catalog 一致性的必要落实，原文没有完整伪代码 |

**项目接口约定：**不存在目录的查询返回空集合并附 `exists=false`，不创建目录；存在的空目录返回空集合且 `exists=true`。范围集合必须按 ID 去重。这里不定义 ANN 的不足 k、并列距离或 Recall 规则，它们属于 SEARCH-01。

### MOVE 的输入检查

- 源与新父目录都必须存在；不移动根目录，不把目录移到自己或自己的后代。
- 新父目录已经有同名孩子时拒绝，不自动退化为 MERGE。
- 源原父目录恰为新父目录时，作为 no-op 返回成功，结构和集合不变。
- 上述拒绝/no-op 规则是项目约定，原文只描述了合法 MOVE 的主要路径。

### MERGE 的输入检查

- 两根必须存在且互不为祖先/后代；根目录、自合并和包含关系合并初版拒绝。
- 同名目录冲突属于 MERGE 的正常工作，不因冲突丢掉条目。
- 不按展示文件名覆盖 payload；单父目录合法域中两个不相交源/目标子树没有重复 entry ID。
- 目录根清理、空源情况和返回错误由统一接口约定控制；不引入“合并后自动删所有空祖先”的隐含操作。

## 4. 三方案必须保留的区别

| 操作 | PE-ONLINE | PE-OFFLINE | TrieHI |
|---|---|---|---|
| 写入 | 直接父目录 posting | 祖先 posting | 沿祖先节点更新 Inc |
| 递归 | 枚举子树路径并集合 | 读一次祖先物化 posting | 路径定位后读节点 Inc |
| 非递归 | 直接 posting | 总集合减直接孩子子树并集 | 总集合减直接孩子 Inc 并集 |
| MOVE | 重映射全部受影响目录路径键 | 路径重映射并更新变化的祖先 | 重连源节点并更新变化的祖先 |
| MERGE | 路径键映射与冲突集合并 | 同左，另维护祖先 | 不冲突子树整体转挂，冲突节点递归协调 |

依据：PDF pp. 4–7，§III/IV、表 I/II。共同祖先不需要重复减加；bitmap 运算耗时不被视为常数。公共 catalog 的更新是正确性义务，即使原文某些计时排除了它也必须完成。

独立判定器将从“ID→直接父目录”的简单记录逐条计算祖先/后代关系；不调用任何方案的 posting/Inc 逻辑，不能被某方案借用作额外索引。

## 5. 原文图 2 的初始人工真值

ID 使用原图 doc_1…doc_9 的数字，与真实数据的 0 起始 ID 空间区分。**以下是原图的人工推导预期，不是运行结果。**

| 目录 | 非递归 Local | 递归 Scope |
|---|---|---|
| `/` | 空 | `{1,2,3,4,5,6,7,8,9}` |
| `/HR/` | `{1}` | `{1,2}` |
| `/HR/Policies/` | `{2}` | `{2}` |
| `/Finance/` | `{3}` | `{3}` |
| `/Legal/` | `{4}` | `{4}` |
| `/Dept_A/` | `{5}` | `{5,8}` |
| `/Dept_A/OKR/` | `{8}` | `{8}` |
| `/Dept_B/` | `{6}` | `{6,9}` |
| `/Dept_B/OKR/` | `{9}` | `{9}` |
| `/Archive/` | 空 | `{7}` |
| `/Archive/HR/` | `{7}` | `{7}` |

来源：PDF p. 3，图 2；对照 PDF p. 6 图 5 的 Inc。

### CASE-MOVE：从初始图独立开始

输入 `MOVE('/Dept_A/', new_parent='/Dept_B/')`：

- `/Dept_A/` 与其旧子路径不存在。
- `/Dept_B/Dept_A/`：Local `{5}`，递归 `{5,8}`。
- `/Dept_B/Dept_A/OKR/`：Local/递归均 `{8}`。
- `/Dept_B/`：Local `{6}`，递归 `{5,6,8,9}`。
- 原 `/Dept_B/OKR/` 仍为 `{9}`；其他根分支不变；根集合仍为全部九个 ID。
- catalog：5 指向新的 Dept_A 节点/路径，8 指向它的 OKR；向量引用不变。

### CASE-MERGE：重新从初始图独立开始，不接在上例后

输入 `MERGE('/Dept_A/', target='/Dept_B/')`：

- `/Dept_A/` 旧绑定消失；不会创建 `/Dept_B/Dept_A/`。
- `/Dept_B/`：Local `{5,6}`，递归 `{5,6,8,9}`。
- `/Dept_B/OKR/`：Local/递归均 `{8,9}`。
- catalog：5 归 Dept_B，8 归目标 OKR；6、9 的逻辑归属保留；根集合仍为全部九个 ID。

### CASE-BOUNDARY 与 CASE-ERROR

另建小树区分 `/a/`、`/ab/` 和 `/a/b/`；在父节点和孩子都放条目，验证递归/非递归区别。分别检查缺失目录、现存空目录、MOVE 到自己的后代、同名孩子冲突、MERGE 自身/包含关系；拒绝前后的完整逻辑状态应相同。后续实施时保存固定输入，不能把这些预期提前登记为测试通过。

## 6. 真实数据与原文对照的边界

- WIKI 查询缺目录约束、DSM 序列未恢复，不能由图 2 正确就认定原文实验已复现。
- ARXIV 多类别可用于后续范围语义核查，但当前不足以确定作者的 DSM 处理。保留全部原始信息，合法域以单父目录核心为限，不悄悄把它放宽成另一种算法。
- 两套 ARXIV 真值有后代范围结果，不直接作为非递归真值；距离和归一化未确定，不定义原文质量验收通过。
- 当前 OpenViking benchmark 的路径加载行为与本项目要求不同，详见 `reference-loader-review.md`。不能直接用它来解除上述缺口。

因此可以先落实单父目录核心的人工输入和正确性判定；真实多类别维护、正式数据质量曲线仍保留前置条件。具体实现/环境进度以 PLAN/STATE 为准。

## 7. SPEC-TIME-PILOT-01：固定时间目录正确性协议

2026-10-26：前 10,000 行 corpus metadata 的 ID=0…9999，采用独立 time 命名空间视图，每个 ID 只使用它原有的一个 time 字符串作为本视图父目录。目录表示仅增加前导/末尾斜杠，月份原拼写不改。categories 原值完整保留在 source-metadata.jsonl，没有选首类别或删除标签。

实际输入为 3 个年份、30 个月份和根，共 34 个目录；目录逐项直接条目数/递归条目数已由源记录独立核对。清单、映射、哈希和准备命令见 data-audit.md §11。这是项目小样本视图，不是作者物理命名空间设计或原始 query/DSM workload 的证明。

当前接口在 `../code/include/directory/index.hpp`：ID 为 uint32；insert 只接收 ID 和父目录，向量由外部维护，本轮不装载。query 返回 exists 与独立位图；ErrorCode 明确拒绝行为，重复 ID 检查先于建目录。预条件拒绝保证逻辑状态不变，不保证 bad_alloc 后事务回滚。
