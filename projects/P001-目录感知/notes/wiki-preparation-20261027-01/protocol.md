# WIKI 小规模目录准入协议 — WIKI-CHECK-01

冻结于本次执行之前，2026-10-27。数据审计不是性能实验；本协议不声称恢复作者的 456 条查询目录或 2000 条 DSM 序列。

- 输入：WIKI-DATA-01 全量核查后的 10000 个等间隔原始 ID/路径，`floor(i*(1941679-1)/9999)`；不依据查询文本、向量相似度或 qrels 选择。原始数据只读。
- 复用现有三方案核心和 `code/tests/oracle.cpp`，不修改目录算法。新增独立的 WIKI 验证入口及隔离构建目录；运行前保存源哈希。
- 目录构造：对每条样本路径创建其目录并插入原始 global ID。显式加入两个空目录 `/__wiki_check__/`、`/__wiki_empty__/`，与真实路径冲突时失败，不改名重试。
- 查询：每个阶段从 oracle 目录按深度分层，每层将 UTF-8 字节序排序目录等间隔选至多 8 个；另查根、上述空目录、缺失路径、维护源/目标/移动后路径。两模式均查。所有目录的树结构、catalog 与 bitmap 不变量全量验证，查询集合对抽取路径逐项零差异。此为正确性压力输入，不是原文工作负载。
- 操作：初始状态检查；按输入路径 UTF-8 字节序选第一个与最后一个互不包含的末端路径作 source/target；MOVE source 到专用空父目录，检查；MERGE 移动后路径到 target，检查；尝试将 target 移到其自身，要求与 oracle 同错误码且目录/catalog 不变，再检查。选择失败时记录失败，不按运行结果换样。
- Release 与 MSVC AddressSanitizer 各执行一次；使用同一输入及源码；保存命令、退出码、完整日志、每个查询的候选数量和 ID 摘要。跨构建查询输出须完全相同。运行只是正确性测试，不报告其耗时为性能结果。
- 每个进程上限 180 秒、private 2GiB、系统可用内存至少 2GiB；超过即终止并保留。ASan 子进程按现有构建配置添加运行时 DLL 路径，不修改全局环境，不安装依赖。
- 通过条件：数据审计和独立复核通过；两构建均零差异、无 ASan 报错；所有核心文件与 006 source-hashes 清单匹配。仅关闭当前单父目录真实路径样本正确性准入，不关闭 WIKI 作者协议、质量或性能任务。
