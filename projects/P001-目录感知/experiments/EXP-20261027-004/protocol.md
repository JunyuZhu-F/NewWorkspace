# PROTO-01 — 小规模目录性能协议（冻结稿）

- 冻结日期：2026-10-26，Asia/Hong_Kong。
- 对应目标：`TASK.md` OBJ-03；后续执行任务：`DIR-01`。
- 状态：**协议已冻结，尚未实施基准驱动，尚未运行性能实验。**
- 正确性基线：`SNAP-dd12b2f5ac546566`，CRoaring v5.3.2；输入与测试证据见 `core-review.md`、`core-implementation-20261026-01/validation-record.json`。
- 协议性质：本项目的小规模、单父目录、串行诊断协议，**不是作者原始工作负载，不用于声称原版 Viking 数值复现**。

## 1. 目的、范围与可接受结论

在相同机器、输入、操作顺序、Release 优化配置和 CRoaring 版本下，比较 PE-ONLINE、PE-OFFLINE、TrieHI 的：

1. 递归/非递归 DSQ 延迟及候选规模；
2. MOVE、MERGE 的完整维护延迟与目录/catalog 成本；
3. 内存内构建时间、目录/catalog 空间及进程内存；
4. 延迟分布和工作计数差异，而非只比较单次均值。

本协议不加载向量，不执行 ANN、训练、质量评价或全量实验。结果只能表述为“当前独立实现、当前 Windows 机器、当前项目工作负载下的实测趋势”。未达到论文趋势或加速倍数也必须保留；不得为追求趋势更换输入、删除异常或改写口径。

## 2. 冻结基线与执行前置

DIR-01 启动前必须满足：

- CHECK-01、ENV-01、DATA-TIME-PILOT-01、SPEC-TIME-PILOT-01 保持有效；真实 ARXIV 类别/WIKI 缺口不解除，但也不阻塞这两个语义明确的项目输入。
- 固定本协议文件的 SHA-256。任何影响输入、顺序、重置、重复、计时或统计的变更都必须新建协议版本；不得在看到结果后静默修改本稿。
- 基准实现只能新增驱动、计时和只读统计能力，不得给 PE-OFFLINE/TrieHI 增加 Local 查询缓存，不得从 catalog 或 oracle 计算查询答案，不得改变三方案维护算法。
- 新增或修改代码后保存新的完整源码快照/哈希；重跑 Release 与 RelWithDebInfo-ASan 各 7/7 正确性测试。ASan 只用于正确性，不用于计时。
- 实际性能运行前在 `EXPERIMENTS.md` 登记真实实验编号，并在对应 `experiments/<编号>/` 保存协议、配置、代码和输入快照。仅写本协议不登记虚构实验。
- 若前置检查失败，DIR-01 标记阻塞或失败，不输出性能结论。

## 3. 输入与操作序列

### 3.1 通用规则

- 三种策略收到完全相同的内存内 `(ID, parent_path)` 序列；输入文件解析和 TSV/JSON I/O 不进入构建或操作计时。
- ID 和路径顺序固定，不由性能结果重新排列。所有策略使用同一进程重复编号和操作序号。
- 人工树使用 `operation-spec.md` §5 的 9 个 ID、11 个目录；插入顺序为 ID 1…9，对应父目录保持该节真值表。
- 时间视图只使用 `time-pilot-20261026-01/bindings.jsonl`，ID 0…9999 按文件顺序插入；其 SHA-256 必须为 `9aa84f093dfd4e9c4e1633c22ae7a9df424809fee9f45fc22fb96f85c04f36b6`。
- 时间视图保持 3 个年份、30 个月份和根共 34 个初始目录；月份拼写不改，不读取向量、类别、查询或 GT 文件。
- 查询路径顺序为：根 `/` 优先，其余路径按规范路径 UTF-8 字节字典序。路径清单从冻结输入独立生成并保存，不在计时中调用验证接口生成。

### 3.2 工作负载 A：图 2 人工树

| 子负载 | 冻结操作 | 口径 |
|---|---|---|
| `figure2-build` | 从空索引按 ID 1…9 插入 | 构建与初始空间诊断 |
| `figure2-dsq` | 对全部 11 个目录分别执行递归、非递归查询 | 只测初始状态；用于接口/计时诊断，不声称大数据趋势 |
| `figure2-move` | 每个样本从初始图独立构建，执行 `MOVE('/Dept_A/', '/Dept_B/')` | 与 MERGE 不连续执行 |
| `figure2-merge` | 每个样本从初始图独立构建，执行 `MERGE('/Dept_A/', '/Dept_B/')` | 与 MOVE 不连续执行 |

人工树很小，尾部延迟主要反映计时器、分配器和背景扰动；必须单独报告，不与 10,000 条输入合并统计。

### 3.3 工作负载 B：10,000 条时间视图 DSQ

- 只测初始状态的 34 个目录。
- 每个 sweep 先按冻结路径顺序完成全部递归查询，再按同一路径顺序完成全部非递归查询，共 68 次查询。
- 每次查询记录路径、模式、深度、直接孩子数 `c`、查询涉及目录数、返回候选数和总时延。
- 查询结果在计时外计算 cardinality/校验摘要；候选集合必须与该状态独立判定器一致。查询后销毁结果，析构和正确性检查不计入单次 DSQ 时延。
- 维护后的 DSQ 仅做正确性检查，不混入本稿的初始状态性能分布。

### 3.4 工作负载 C：10,000 条时间视图 DSM

每个测量样本都从相同初始时间树开始，按以下顺序连续执行：

1. `MOVE('/1992/1/', '/1991/')`：源 193 条；操作后 `/1991/` 递归 499、`/1992/` 递归 3,068。
2. `MERGE('/1992/7/', '/1991/7/')`：296 条并入目标原有 2 条，目标为 298；操作后 `/1991/` 递归 795、`/1992/` 递归 2,772，目录数 33。
3. 拒绝 `MOVE('/1992/8/', '/1991/')`：源 226、同名目标 28；状态不变。拒绝时延单独报告，不并入成功 MOVE/MERGE 分布。

MOVE 与 MERGE 之间不重置；每个完整序列之间必须销毁旧索引并从冻结绑定重新构建。序列外构建、销毁和 oracle 检查不进入单项维护时延，但计入进程总 wall-clock 记录。数量锚点用于定位错误，不能替代逐 ID 集合核验。

## 4. 重复、预热、重置与运行顺序

- 每个“策略 × 工作负载 × 子负载”执行 **5 个独立测量进程**，记为 run 0…4。
- 每个测量进程先执行 **3 个完整预热迭代**，再执行 **20 个测量迭代**；预热数据标记 `warmup=true`，不得纳入性能统计。
- `build` 的一个迭代是从空索引完成一次构建；`dsq` 的一个迭代是一个 68 查询 sweep（人工树为 22 查询）；`dsm` 的一个迭代是上述完整序列。每个 build/DSM 迭代使用全新索引，DSQ 在同一初始索引上预热后测量，属于**暖索引、暖代码路径**口径。
- DSQ 不在 sweep 间重建；DSM 不在 MOVE/MERGE 间重建。不得把两种重置口径混为一谈。
- 一个进程只运行一种策略和一个子负载，避免同进程三策略相互污染。进程启动/退出不进入操作时延，另记进程 wall-clock。
- 外层按 run 循环移位策略顺序：run 0 为 ONLINE→OFFLINE→TRIE，run 1 为 OFFLINE→TRIE→ONLINE，run 2 为 TRIE→ONLINE→OFFLINE，run 3 重复 run 0 顺序，run 4 重复 run 1 顺序。工作负载顺序固定为 figure2→time，build→dsq→move/merge；保存实际启动顺序和时间。
- 单线程、无并行查询；不改变 CPU 亲和性、进程优先级或系统电源设置作为本轮基线。记录这些实际状态，不宣称机器完全空闲或缓存受控。

## 5. 计时口径与分阶段诊断

### 5.1 主口径：公开 API 总时延

- 使用 C++ `std::chrono::steady_clock`，整数纳秒保存；运行前记录 `is_steady` 和实际分辨率。
- 每个进程在预热前执行 10,000 次空计时区间，保存计时开销分布；**不从测量值中减去开销**。
- DSQ 主计时从调用 `query(path, recursive)` 前开始，到返回的 `QueryResult` 构造完成后结束。包含路径解析/定位、bitmap 获取与返回副本、集合并/差及公共开销；不含 cardinality、oracle、结果析构和输出 I/O。
- DSM 主计时覆盖整个公开 `move`/`merge` 调用，包含合法性与冲突检查、目录结构更新、posting/Inc 更新、公共 catalog 更新和冲突扫描；不含前置构建、后续验证和结果写盘。
- 构建主计时从空索引构造前开始，到全部插入完成后结束；包含目录和 catalog，不含输入文件解析及旧索引析构。
- 主比较使用未启用内部分段计时探针的同一 Release 核心，避免探针开销改变主要结果。

### 5.2 次口径：分段插桩诊断

若 DIR-01 增加内部探针，必须构建独立诊断可执行文件，保持相同输入、优化级别和重复矩阵，结果标为 `instrumented=true`。其总时延不得与未插桩主结果混池或直接计算加速比。

DSQ 尽可能分列：路径解析/定位、bitmap 获取与返回复制、集合并/差、未分配余量和公开 API 总时延。DSM 尽可能分列：预条件/路径定位、目录核心更新、公共 catalog 更新/冲突扫描、未分配余量和公开 API 总时延。各阶段必须来自真实计时；无法隔离时写 `not_collected`，不得用计数或减法伪造分项。

同时保存现有 `MaintenanceWork`：`remapped_path_keys`、`relinked_subtrees`、`reconciled_nodes`、`catalog_entries_scanned`，并增加实际查询路径/位图访问计数。目录净成本与完整系统成本同时报告；“排除 catalog”不能成为漏做 catalog 更新的理由。

## 6. 工作负载特征与输出粒度

每条 DSQ 原始记录至少包含：协议版本、实验/运行编号、时间戳、策略、输入及代码哈希、run/iteration/sweep、路径、递归标志、目录深度、`c`、实际遍历目录数、候选数、bitmap 获取/复制计数、各真实计时项和 `warmup` 标志。

每条 DSM 原始记录至少包含：操作类型、source/target/new_parent、是否接受、源/目标深度、源子树目录数、源子树条目数 `m_u`、目标条目量、冲突节点数、全部 `MaintenanceWork` 计数及各真实计时项。本文中的 `m_u` 明确定义为**源目录递归条目数**；若以后证明原文符号含义不同，保留字段并更正命名，不改写历史值。

每条构建记录包含条目数、目录数、插入顺序哈希、构建总时延。原始输出采用 JSONL 或等效逐行结构化格式；汇总文件不得代替原始逐操作记录。

## 7. 统计规则

- 只统计 `warmup=false` 且通过运行内正确性检查的样本；失败运行完整保留，但不能只删除失败样本后宣称通过。
- 按“输入 × 策略 × 子负载 × 操作/查询模式 × 路径（查询另报）”分组。人工树与时间视图、递归与非递归、成功 MOVE/MERGE 与拒绝操作不得混池。
- 保存并报告每个进程的均值，同时给出跨 5 进程 pooled 逐操作值的算术均值、P90、P95、P99、P99.9 和样本数 N。
- 分位数统一使用 **nearest-rank**：对升序样本 `x[1…N]`，`Q(p)=x[max(1,ceil(p×N))]`，不插值。实现与汇总脚本必须固定并留存。
- N<10,000 时 P99.9 只作描述性尾部观测并明确“不稳定”；DSM 每类仅约 100 个测量样本，不据此声称可靠尾部分布。重复查询也不是独立统计实验，不据此做显著性推断。
- 若报告加速比，使用“同组基线均值 ÷ 本策略均值”，同时给出两组原始汇总；不得平均各查询的加速比或只选有利路径。

## 8. 构建与空间口径

- 构建和空间分别记录目录模块、公共 catalog、向量模块和进程总量。本协议 `vector_bytes=0`、`vector_loaded=false`，不能与论文含向量的总索引大小直接比较。
- 目录逻辑占用应包含节点、路径字符串、posting/Inc 位图及其动态容量；catalog 逻辑占用包含 ID→目录句柄映射。共享目录对象只计一次，所有权分类在配置中说明。
- 逻辑 `live_bytes` 与 CRoaring portable bitmap 大小（若采集）必须分别命名；它们不是完整序列化索引大小，也不能直接对齐论文表 V。
- Windows 进程指标至少记录构建后当前 working set、private bytes 和 peak working set；记录采集 API。进程峰值包含构建/分配器影响，不冒充目录序列化大小。
- 空间采集在计时区外进行。初始状态为必测；维护后空间可作为单独诊断，不能与初始状态混合。

## 9. 正确性门与异常处理

- 新增基准/插桩代码后，先通过既有 Release 和 ASan 各 7/7；随后用一个不计时迭代检查所有输入、操作锚点和返回集合。
- 每个新初始状态至少进行一次全目录两模式逐 ID oracle 核验；每次 DSM 序列后在计时外核验拓扑、catalog、Inc、全局 ID 和拒绝操作无状态变化。
- 每个被测查询在计时外计算确定性摘要并与冻结预期比较，防止空操作或被优化掉的调用产生“更快”结果。摘要算法和预期文件在运行前固定。
- 任一集合差异、崩溃、超时、哈希不符、输出缺失或资源停止均使相关运行失败/中断；不得生成正常汇总或宣称趋势复现。
- 编译或 CTest 时间、开发正确性测试的耗时不得写入 DSQ/DSM 性能结果。

## 10. 资源与停止上限

以下是本项目资源保护上限，不是论文参数：

- 仅图 2 与固定 10,000 条 metadata 时间视图；不读取向量，不扩展到全库。
- 单进程 private bytes 达 2 GiB、系统可用物理内存低于 2 GiB、单进程超过 120 秒或 DIR-01 总 wall-clock 超过 30 分钟，停止新运行并保存中断状态。
- 原始结构化输出上限 1 GiB；达到上限即停止，不删除旧证据换取空间。
- 不安装 Linux/WSL，不购买资源，不启动 ANN 或大规模参数搜索。触及上限后只能报告已完成部分及阻塞，不能自行减少重复数或改小输入继续充当原协议。

运行前后记录 OS、CPU 型号/逻辑核数、可见/可用内存、电源模式、编译器与 CMake/Ninja 版本、实际编译参数和明显背景负载。异常高负载只如实记录，不选择性删除运行。
